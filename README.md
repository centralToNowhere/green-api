# Telegram · GREEN-API

Веб-клиент личных текстовых переписок Telegram. React, TypeScript, Vite, React Router, TanStack Query, Base UI, CSS Modules, MobX и mobx-persist.

## Запуск

Требуются Node.js, совместимый с Vite 8 (22.12+), и Yarn 4.

```bash
yarn install
cp .env.example .env
# Укажите VITE_GREEN_API_URL из настроек вашего инстанса
yarn dev
```

Адрес API общий для приложения и задаётся при сборке. Для входа нужны `idInstance` и `apiTokenInstance` уже авторизованного Telegram-инстанса. Запросы выполняются напрямую из браузера: сервер API должен разрешать CORS для адреса приложения. QR-код и авторизация Telegram-инстанса выполняются в личном кабинете GREEN-API.

## Настройка уведомлений

В настройках инстанса оставьте `webhookUrl` пустым и включите `incomingWebhook`, `outgoingMessageWebhook`, `outgoingAPIMessageWebhook` и `outgoingWebhook`. Приложение само эти настройки не изменяет. Используйте один активный потребитель очереди для инстанса: несколько вкладок или другие клиенты могут забирать уведомления друг у друга.

Клиент получает уведомления через long polling с `receiveTimeout=5`: сервер может ожидать новое уведомление до 5 секунд. После успешного запроса, включая пустой ответ, интервал до следующего опроса составляет 100 мс, после ошибки — 5 секунд. Опрос продолжается и в фоновой вкладке.

После обработки клиент подтверждает уведомление через `DeleteNotification` и объединяет историю и уведомления по ID сообщения. Пустой ответ не считается ошибкой. При ошибке удаления уведомление обрабатывается повторно без дублирования сообщения. Ошибка опроса показывается в Toast один раз до восстановления связи.

Документация: [HTTP API](https://green-api.com/telegram/docs/api/receiving/technology-http-api/), [ограничения запросов](https://green-api.com/telegram/docs/api/ratelimiter/), [отправка](https://green-api.com/telegram/docs/api/sending/SendMessage/).

## Поведение и хранение

- Поддерживаются личные чаты и текст, включая текстовые сообщения со ссылками. Группы, каналы, вложения и звонки не поддерживаются.
- История загружается для каждого чата при входе и повторно при его открытии, по 100 последних сообщений. Запросы истории запускаются не чаще одного раза в 1,1 секунды; открытый чат имеет приоритет. Постраничная загрузка более старой истории не реализована.
- Отправка: Enter; новая строка: Shift+Enter. Лимит — 4096 символов. При ошибке отправки текст остаётся в редакторе; автоматической повторной отправки нет.
- Сессия хранится в `sessionStorage` до закрытия вкладки или выхода. Токен не включается в ключи Query Cache и сообщения об ошибках.
- Черновики сохраняются через MobX и mobx-persist без декораторов, в `localStorage`, ключ `green-telegram-drafts`. Внутренний ключ — JSON-пара `[idInstance, chatId]`. API URL и токен в него не входят. Выход сохраняет черновики, но очищает сессию и серверный кэш.
- Мобильная версия показывает одну панель, десктопная — две. Точки адаптации: 640, 768, 1024 и 1280 px. Тёмная тема соответствует локальным дизайн-референсам.

## Команды и проверки

```bash
yarn build       # TypeScript и production-сборка
yarn preview     # просмотр production-сборки
yarn lint        # ESLint
yarn check-types # проверка типов приложения
yarn check-format # проверка форматирования Prettier
yarn format      # исправления ESLint и форматирование Prettier
yarn precommit   # типы → ESLint → unit-тесты → Prettier
yarn test        # Vitest, Testing Library, MSW
yarn test:watch  # тесты в режиме наблюдения
yarn playwright install chromium
yarn test:e2e    # браузерные сценарии Playwright
```

Тесты используют фиктивные данные и перехватывают API-запросы; реальные сообщения не отправляются. Проверяются вход/выход, черновики, ошибки, повторные уведомления, гонки истории, ограничения частоты, мобильная навигация и отправка. E2E автоматически запускает Vite на порту 4173 с тестовым адресом API. Скриншоты находятся в `test-results/`.

Git hook `.githooks/pre-commit` запускает `yarn precommit` перед коммитом. После клонирования подключите его:

```bash
git config core.hooksPath .githooks
```

Production-сборка и E2E-тесты не входят в `precommit` и запускаются отдельно. Prettier использует `.prettierrc`; Markdown, JSON и YAML исключены из проверки и форматирования через `.prettierignore`.

Для ручной проверки используйте настроенный инстанс: откройте личный чат, отправьте текст, ответьте с другого Telegram-аккаунта и проверьте историю и превью. Затем проверьте восстановление черновика после перезагрузки и очистку сессии после выхода.

## Структура

- `src/app/`: провайдеры, маршруты, QueryClient.
- `src/pages/login/`: вход и проверка подключения.
- `src/pages/chats/`: переписка, запросы, обработка уведомлений, черновики.
- `src/shared/`: транспорт GREEN-API, сессия, UI kit.
- `src/test/` и `tests/e2e/`: тестовое окружение и браузерные сценарии.

## Правила разработки

- Используйте алиас `@/` для импортов из `src`, например `import { GreenApi } from '@/shared/api';`. Алиас настроен в TypeScript, Vite и Vitest.
- Соблюдайте настройки ESLint и Prettier: обязательные фигурные скобки, разделение блоков пустыми строками, запрет `debugger` и `console`, кроме `console.warn` и `console.error`.
- TypeScript работает в строгом режиме: проверяет неиспользуемые переменные и параметры, недостижимый код, явный `override` и точные типы опциональных свойств (`exactOptionalPropertyTypes`).
